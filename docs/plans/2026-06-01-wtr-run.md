## Background: why `run` instead of `cd`

A compiled binary is a child process and cannot change its parent shell's working directory. A `wtr cd` verb would therefore have to be either fake (print a path you still must `cd "$(…)"`) or force a shell-function install (`eval "$(wtr shell-init …)"`). Instead, `run` is the primitive a binary *can* do honestly: spawn a child process in a chosen directory.

- `wtr run feat-x npm test` — one-off command in the worktree (what `cd` users actually want most of the time).
- `wtr run feat-x` — no command → interactive `$SHELL` **in** the worktree; `exit` returns you. This covers the "I just want to be there and poke around" case without any shell integration.

## Design

### 1. Command shape & UX

```
wtr run <name> [command...]
```

- `wtr run feat-x npm test` → runs `npm test` in the `feat-x` worktree.
- `wtr run feat-x git status -s` → flags after `<name>` flow to the command (greedy; no `--` needed).
- `wtr run feat-x` → opens an interactive `$SHELL` (fallback `/bin/sh`) in the worktree.
- `wtr run master …` / `wtr run main …` → targets the **main** worktree.

### 2. Name resolution (config-free)

Resolve against the live `git worktree list`, not config/`base_dir`:

1. `name` ∈ {`master`, `main`} → the **main** worktree (first entry of `git worktree list`).
2. else → the worktree whose path **basename == name**.
3. else → `Error: Worktree not found: <name>` (exit 1).

Rationale: only ever resolves worktrees that actually exist; needs no config; robust to `base_dir` changes. Trade-off (documented edge): a worktree literally named `main`/`master` is shadowed by the alias.

Implemented as a pure function so it is unit-testable without git:

```clojure
;; src/wtr/commands.lg
(defn resolve-worktree-path
  "Returns the abs path for `name` from the worktrees vector, or nil.
   master/main → main (first) worktree; otherwise basename match."
  [wts name]
  (cond
    (or (= name "master") (= name "main")) (:path (first wts))
    :else (some (fn [w] (when (= (basename (:path w)) name) (:path w))) wts)))
```

### 3. Execution mechanism

`os/exec*` inherits stdio and returns the child's exit code, but it cannot set the cwd, and let-go exposes no `os/chdir`. Use the bash reference's positional-arg shell wrapper — `exec "$@"` does a real exec (PATH lookup, no re-parsing → no quoting/injection risk):

```clojure
;; cmd is a vector (possibly empty); shell falls back to /bin/sh
(let [shell   (let [s (os/getenv "SHELL")] (if (str/blank? s) "/bin/sh" s))
      cmd-vec (if (empty? cmd) [shell] cmd)
      code    (apply os/exec* "sh" "-c"
                     "cd \"$1\" || exit 1; shift; exec \"$@\""
                     "sh" dir cmd-vec)]
  (os/exit code))
```

- `$1` = dir, then `shift`, then `exec "$@"` = the command (or `$SHELL` when none given).
- stdio inherited → streaming + interactive; exit code propagated via `os/exit`.
- No stdout notice — keeps piped output clean (the prompt / `pwd` already shows location).

### 4. Cross-repo changes

**lgx** — advertise dev-vs-bundled via env. In the `run` path, set `LGX_RUN=1` before spawning lg. The child lg process inherits it (lgx spawns via `os/sh`, which inherits the parent env). This lets any lgx-built tool reliably tell it is running under `lgx run` (dev) vs. as a bundled binary, without sniffing argv for `--`.

**tiny-cli** — greedy variadic trailing arg. Add a `:variadic {:key … :doc …}` spec alongside `:args`. Once the fixed `:args` are filled and a `:variadic` is declared, the parser switches to **rest mode**: every remaining token (including `-x` and `--`) is appended verbatim, and `finalize-context` buckets the first N positionals into the named args and the remainder into a vector under the variadic key (no "Too many arguments"). Constraint: a command's own options cannot appear after the variadic begins — fine for `run` (it has no options). This is `.cljc` and must pass on let-go, Clojure, and Babashka.

**wtr** — fix `cli-argv` and add the command. Replace the fragile "is there a `--` anywhere?" mode test (which misfires whenever a *user* command contains `--`, e.g. `git checkout -- file`) with an `LGX_RUN`-keyed split, factored into a pure, testable helper:

```clojure
;; src/wtr/args.lg  (new, ns wtr.args)
(defn strip-runner-args
  "Return the application args from a raw argv.
   dev (under lgx run): drop up to and including lgx's injected `--` marker.
   bundled binary:      drop argv[0] (the program name)."
  [argv lgx-run?]
  (if lgx-run?
    (rest (drop-while #(not= "--" %) argv))
    (rest argv)))
```

`main.lg`'s `cli-argv` becomes `(strip-runner-args argv (not (str/blank? (os/getenv "LGX_RUN"))))`.

### 5. Error handling

- Not a git repo / `git worktree list` fails → reuse the `list`/`create` pattern (print git stderr, exit 1; `git/worktrees` throws ex-info with `:stderr`).
- Worktree not found → `error-exit` "Worktree not found: <name>" (exit 1; helper prepends `Error:`).
- Missing `<name>` → tiny-cli "Missing argument" (exit 2).
- Command not found → sh's `exec` fails → 127, propagated naturally.
- `cd` fails at runtime (dir removed between resolution and exec) → wrapper `exit 1`.

### 6. Why interactivity needs the built binary

lgx's dev runner (`lgx/runner.lg`) currently spawns lg via `os/sh`, which buffers stdout/stderr and leaves stdin dead (there is a standing TODO to switch to inherited stdio). So under `lgx run`, a nested interactive `$SHELL` and live streaming won't work — wtr's child inherits buffered pipes, not the tty. **Verify `run` against the built binary.** (Switching lgx's runner to the new `os/exec*` is a separate lgx improvement, out of scope here.)

- **Three-way dev wiring.** Development uses local lgx binary (rebuilt in Task 2) + local tiny-cli (`:local/root`, Task 3) + local lg. Don't forget Task 8 reverts these to released pins.
- **tiny-cli is `.cljc`** — the variadic change must pass let-go, Clojure, and Babashka (`lgx test-all`).
- **Greedy variadic constraint** — a command's own options can't follow the variadic; `run` has none, so global options (e.g. `--base-dir`) must precede the command, which is conventional (`env`, `nohup`, `time`).
- **Interactivity** only works in the built binary until lgx's runner adopts inherited stdio (separate improvement).
- **Shell wrapper assumes a POSIX `/bin/sh`** — fine for macOS/Linux; Windows is already unsupported (path handling throughout uses `/`).

## Out of scope (YAGNI)

- `wtr cd` shell integration (`wtr shell-init`) — `run` covers the need without rc-file setup.
- Switching lgx's dev runner to `os/exec*` (would make `lgx run` interactive/streaming).
- Honoring `--base-dir` for `run` (resolution is config-free by design).
- Ambiguity handling when two worktrees share a basename (resolves to the first match; documented).
